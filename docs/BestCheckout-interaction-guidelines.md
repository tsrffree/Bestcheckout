# BestCheckout 原型交互通则

从整个 BestCheckout 商家后台 / 官网原型抽象. 只写可复用的交互与表现原则, 不写具体业务规则 (如 Pixel 条数、Bundle 互斥).

适用面: Overview / Purchase flows / Checkout pages / Bundles / Subscriptions / Orders / Settings / Help / 编辑器全屏工作台.  
对照实现: `assets/theme.css`、`assets/shell.js`、各模块 `js/app.js`.

---

## 1. 总则

1. **一家后台, 一套壳.** 顶栏 + 侧栏由 shell 持久挂载; 模块只渲染 `#root` 内容区, 不各自再造导航.
2. **英文源文案, 中文 runtime overlay.** 菜单、按钮、toast、对话框、破坏性操作在源码里写英文; 翻译靠 i18n, 不在业务模块硬编码中文系统文案.
3. **商家语言, 少实现细节.** 状态与提示写商家要处理的结果 (如 In Shopify / Needs attention), 不默认暴露 shop_id、schema、webhook、队列名.
4. **同能力同交互.** 列表、弹窗、空态、删除确认、未保存门禁在各模块对齐; 新页优先复用现有模式, 不另起一套.
5. **可点可预览.** 原型要能走完主路径: 列表 → 详情 / 编辑 → 保存 / 放弃 → 回列表; 用 demo 店和 mock 态覆盖空态与异常态.

---

## 2. 壳与导航

| 原则 | 约定 |
|---|---|
| 布局 | 顶栏全宽 + 下方圆角内容卡 (侧栏 + `#root`) |
| 侧栏 | 一级菜单 + 可选子项; 当前路由高亮; 子组可折叠 |
| 设置 | Settings 可走全屏设置壳 (左设置导航 + 右内容), 或侧栏子路由直达 |
| 店铺上下文 | 顶栏可切换 demo 店; `?store=` 写入会话, hash 跳转后仍保持 |
| 连接态 | 未连接可跳出公共连接流; 进行中 / 失败态留在后台可见 |
| 返回 | 详情 / 编辑页用返回箭头或明确 Exit / Back, 回到列表或进入前的来源页 |

一级菜单只暴露 Checkout 增长相关能力; 不把完整电商后台导航塞进本产品.

---

## 3. 页面骨架

标准内容页自上而下:

1. **页头:** `page-title` (约 20px / 600) + 可选一句 muted 说明 + 右侧主操作
2. **筛选 / Tab 区** (如有): 与下方内容同卡或紧贴卡片顶
3. **主内容:** `panel` 卡片, 内用 `.tbl` 表格或卡片网格
4. **底栏:** 分页或「Total N records」类汇总 (列表页)

间距习惯: `#root` 约 `20px 24px 40px`; 卡片 `border-radius: 12px`, 内边距约 `16px` (`card-pad`).

**详情页双栏:** 主列 + 约 275px 右侧信息轨 (`detail-wrap` / `detail-cols`); 编辑器预览轨可 sticky.

---

## 4. 视觉与控件尺度

| 元素 | 约定 |
|---|---|
| 主色 / 品牌 | `--brand: #0066e6`; 成功绿 / 警告 / 错误红用 token |
| 正文字号 | 正文约 14px; 表格约 13.5px; muted 说明约 12–13px |
| 主按钮 | `.btn` 高约 32px; 筛选条内可 34px |
| 卡片内次要添加 | 可 28px 高 (与渠道卡添加按钮对齐时) |
| 输入框 | `.input` 高约 36px; focus 描边品牌色 |
| 圆角 | 控件约 8px; 面板约 12px |
| 图标按钮 | 约 32×32 |

颜色语义: 绿 = 就绪 / 成功; 橙 = 进行中 / 需关注; 红 = 失败 / 危险; 灰 = 中性 / 未启用; 蓝 = 信息 / 产品标记.

---

## 5. 按钮与操作层级

| 层级 | 用法 | 样式 |
|---|---|---|
| Primary | 页内唯一主行动: Save / Update / Create / Connect / Publish | `.btn-primary` |
| Default | Cancel / 次要并行操作 / 打开外部 | `.btn-default` |
| Gray / quiet | Edit / Link / Copy / 工具性操作 | `.btn-gray` 或等价弱按钮 |
| Danger | 确认后的删除 / 取消订阅等破坏性确认键 | 红底或 `danger` 确认 |

规则:

- 一屏通常只有一个 Primary.
- 破坏性操作不直接生效: 先确认弹窗; Cancel 关闭且不改数据.
- 忙碌态按钮可 disabled, 文案改为 Saving… / Syncing… / Publishing….
- 行内 Action 列优先短文字链或弱按钮 (Edit / Delete), 右对齐或居中固定窄列.

---

## 6. 列表与表格

**默认列表形态:** `.tbl` 全宽表 + 行 hover + 行可点进详情 (若该实体有详情).

| 原则 | 约定 |
|---|---|
| 表头 | 左对齐、加粗; 数字列 `.num` 右对齐、等宽数字 |
| 行高与单元格 | 约 `12px 16px` 内边距; 默认 nowrap, 长文本用 ellipsis |
| 筛选 | 顶栏 keyword / 时间 / 范围等; 已生效条件用可清除的 tag chip |
| Tab | 状态 Tab 与搜索条件正交; Tab 角标反映「当前搜索下」的数量 |
| 分页 | 底栏 Total + 分页; 或业务规定全量展示时明确「无分页」 |
| Action 列 | 固定窄列; 无权限或不可删时不展示入口, 而不是灰掉误导 |

**对齐员工列表时的列表通则 (配置类多行实体):**

- 列结构清晰: 主键 ID / Source / Name / 关键配置 / Action
- 不堆无关 Status、Pages 类装饰列, 除非该页确有独立状态机需要展示
- Source 等枚举用商家可读文案 (如 Shopify store / Manual setup)
- 超长凭证或密钥: 展示原文或截断 + hover 全文; 无值用 `—`
- 排序可把「当前生效 / Primary」类行置顶, 但规则写在业务 PRD; 交互上保持稳定可预期

**卡片网格列表** (如 Pages 库): 筛选 pill Tab + 计数 + 网格卡片; 卡片含预览缩略、名称、状态、快捷 Duplicate / Preview.

---

## 7. 卡片与渠道块

| 形态 | 何时用 | 交互要点 |
|---|---|---|
| 内容 `panel` | 分区说明、表单组、KPI | 标题 + muted 说明 + 正文 |
| 渠道 / 能力卡 | Settings 下多渠道并列 | 卡头左说明、右状态 + 添加; 有数据才渲染表体 |
| 信息提示条 | 引导或只读说明 | 蓝系弱提示, 不阻断操作 |
| Overview 面板 | 指标、趋势、待办 | 空数据给一句「何时会出现」的说明 |

**空渠道 / 空列表卡:** 无行时不渲染空表头骨架; 保留卡头与添加入口即可.

---

## 8. 空态 / 加载 / 异常

| 状态 | 交互 |
|---|---|
| 空列表 | 居中 muted 一句 (如 No orders match these filters.); 有主创建入口时在页头保留 |
| 空图表 / 空动态 | 说明「首笔成功后才会出现」类预期, 不假造数据糊弄 |
| 加载 | 短文案 + 控件 disabled (Syncing…); 避免整页无反馈白屏 |
| 校验失败 | 字段 `has-error` / `is-invalid`; 错误文案紧贴字段 |
| 权限 / 连接不足 | 卡片内告警条 + 明确 CTA (如 Request new install link), 不静默失败 |
| 检测失败 / Not detected | 卡头状态如实展示; 仍提供手动添加路径 (若产品允许) |

---

## 9. 表单

1. Label 在上或按设置页既有 field 栈; 必填用红色 `*`.
2. 只读字段: disabled / readonly 灰底, 仍可见值.
3. 密钥类: 原型可掩码展示; 不在 UI 常驻明文真实秘密.
4. 开关类: 开后才展开依赖字段 (如服务端凭证).
5. 组合输入: 前缀 / 后缀 addon 与输入框拼接成一组 (金额、分钟、域名等).
6. 校验时机: 保存时必检; 关键冲突类可在 Save 与失焦双检; 原型 URL 类可校验提示但不一律阻断 Save (沿用既有控件习惯时保持一致).
7. 成功保存: toast + 关闭弹窗或停留并刷新列表; 失败: 阻断并说清原因.

---

## 10. 弹窗与确认

**标准 Modal**

- 结构: 标题 + 可滚动 body + 底栏 (Cancel + Primary)
- 默认宽约 420–560; 复杂表约 620–760; 能力表可更宽; `max-width: calc(100vw - 24px)`
- 点遮罩或 X 或 Escape 关闭; Enter 在普通 input 上可触发表脚 Primary
- 纯告知可用单按钮 (Got it / Close / Complete) 并 `hideCancel`

**Confirm (破坏性或替换性)**

- 标题问句或短结论 + 正文说明后果
- Primary 用危险色或明确动词 (Delete / Remove / Replace and activate / Cancel subscription)
- Cancel 始终可退且不改数据

**冲突 / 阻断类报错弹窗**

- 只保留标题、说明、关闭; 不提供「强制覆盖」类次要按钮, 除非业务明文允许
- 用于互斥启用、Primary 冲突等「必须先解除现状」的场景

**三键未保存门禁** (编辑器切模板等): Cancel | Discard | Save.

---

## 11. Toast 与轻反馈

- 成功 / 提示: 顶部或底部居中短消息, 数秒消失
- 用于: 已保存、已复制、已删除、已断开、测试事件已记录等
- 不替代必须阅读的确认或错误弹窗
- 文案一句说完, 避免段落

---

## 12. 状态展示 (Pill)

- 统一用 `.pill` + 色语义 (+ 可选圆点)
- 同一实体状态枚举固定映射, 列表与详情一致
- 紧凑场景 (如同步状态) 可用更小 padding / 无圆点变体, 但色义不变
- 列表状态若只读: 徽章不可点改; 改状态走编辑页保存

---

## 13. 全屏编辑器

适用于 Checkout / Thank you 装修、主题编辑器等.

| 原则 | 约定 |
|---|---|
| 结构 | 顶栏 + 左结构树 + 中实时预览 + 右设置 |
| 顶栏操作 | Discard / Save; 需要上线时再加 Publish; Exit / Back 回页面库或来源 |
| Dirty | 有未保存变更时 Discard / Save 可点; 无变更时 disabled |
| 预览 | 编辑中预览反映工作副本; 「商家预览 / 已保存预览」不掺未保存草稿 (主题编辑器约定) |
| 设备 | Desktop / Mobile 切换只影响画布, 不丢编辑态 |
| 删区块 | 确认后可先留在会话内, Save 前可用 Discard 撤回 (文案说明清楚) |

Settings 脏态可用顶部深色 unsaved bar: 文案 + Discard + Update.

---

## 14. 文案与 i18n

1. 源码英文字符串保持稳定, 作为 i18n 词典 key.
2. 品牌名、产品名、第三方名、ID、域名不翻译 (`i18n-skip` / `data-i18n-skip`).
3. 切换语言可整页 reload, 保留 hash.
4. 商家说明用完整句子; 按钮用动词或动词短语 (Save, Add, Connect, Update).
5. 中英文混排时, 控件名与状态枚举保持界面原文.

---

## 15. Demo 与原型元规则

1. 用店铺切换表达不同就绪度 (live / ready / unconfigured / 连接中), 而不是做多套页面.
2. Mock 形状对齐未来 API; 交互上允许「模拟异步」(如域名验证不会假成真).
3. localStorage / sessionStorage 仅用于原型会话 (语言、店、setup、草稿), 不假装成服务端真源.
4. 新功能优先挂在现有 IA 节点下; 不新增与产品边界冲突的一级菜单.

---

## 16. 新开页面自检清单

- [ ] 是否复用 shell, 未自建第二套导航?
- [ ] 页头是否为 title + 说明 + 单一主按钮?
- [ ] 列表是否用 `.tbl` 或已有卡片网格, 空态是否有一句说明?
- [ ] 行内删除 / 替换是否经确认弹窗?
- [ ] 表单必填、只读、错误态是否可见?
- [ ] 保存成功是否 toast? 失败是否阻断?
- [ ] 状态 pill 色义是否与全局一致?
- [ ] 源文案是否英文? 专有名是否 skip 翻译?
- [ ] 是否避免暴露内部实现字段?
- [ ] 是否至少覆盖: 主路径、空态、一个异常 / 阻断态?

---

## 17. 明确不在本通则内的内容

- 具体业务上限、互斥、检测规则、事件映射 → 写在对应 PRD / 验收文档
- BestShopio 主题编辑器控件细则 (色板 T、富文本工具栏等) → 见 `bestshopio-merchant` 的控件 rules; 本仓 Checkout 编辑器只要求「三栏 + Save/Discard」级对齐
- 视觉品牌营销站 (官网 landing) 的动效与营销排版 → 可偏离 Admin 表格密度, 但登录后后台仍遵守本通则

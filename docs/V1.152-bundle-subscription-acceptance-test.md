## 1. 验收范围

### 1.1 本期要验收

| 系统 | 模块 | 功能点 |
|-|-|-|
| BestCheckout 后台 | Bundles | 列表、Add、Edit、Delete、启用互斥、保存后订阅引导、右侧预览悬挂 |
| BestCheckout 后台 | Subscriptions | 列表、Add、Edit、Delete、启用互斥、右侧预览悬挂 |
| BestCheckout 后台 | Contracts | 列表、详情、按状态可执行操作 (Edit shipping address / Retry payment now / Update payment method / Cancel subscription) |
| 店铺前台 / 拦截 | 商品页接管 | Activated 套装接管 Shopify 变体选择区域 |
| 店铺前台 / 拦截 | 拦截脚本 | 覆盖购物车结账与 Buy Now; 勾选订阅必须带订阅标识 |
| 下单 | entry_match / bundle_create / order/create | 单品一次性或订阅拦截落单; 套装加购与本系统建单 |

### 1.2 本期不做 (验收时不作为失败项)

- 套装订单与 Shopify 购物车单品合成一单
- 生成 Shopify 订阅合同; 周期和折扣只用 BestCheckout 自己的计划
- 商家界面出现 shop_id、内部 schema、webhook、队列等词
- 合同如何生成的规则变更 (文档: 本期不改合同怎么生成; 只展示 BestCheckout 结账成功后已生成的合同)
- 从 Shopify / Appstle / Skio / Kaching 导入订阅计划 (须在 BestCheckout 重新创建)

### 1.3 文档「其他」须一并验收

1. Shopify 原生 bundle: 在 upsell 页面可正常显示; 取值从 value id 改为取 sku
2. BestCheckout bundle: 后台选不到 BestCheckout 的 bundle (沿用之前逻辑)

## 2. 环境说明

### 2.1 测试环境

| 项 | 要求 |
|-|-|
| 店铺 | 已连接 Shopify 测试店; 商品已同步到 BestCheckout |
| 账号 | 可登录 BestCheckout 后台的商家账号 |
| 前台 | 测试店商品页、购物车、Buy Now、结账可访问 |
| 数据 | 允许新建 / 启用 / 停用 / 删除套装与订阅; 允许造多条互斥数据 |
| 支付 | 使用测试网关或测试卡; 允许制造 Past due / 取消等合同状态样例 |
| 合同样例 | 准备 Active / Past due / Cancelled 各至少 1 条 (若环境已有生成能力或可预置) |

### 2.2 线上环境

| 项 | 要求 |
|-|-|
| 店铺 | 指定验收商家的正式店 (或灰度店) |
| 账号 | 正式商家账号; 操作前确认商家知情 |
| 前台 | 正式域名商品页、购物车、Buy Now、结账 |
| 数据策略 | 优先用新建 Deactivated 配置做后台验收; Activated 与真实下单须商家确认 |
| 支付 | 真实支付; 尽量用小额 / 可退款订单 |
| 破坏性操作 | Delete bundle / Delete subscription / Cancel subscription 仅在商家确认的测试商品或可回滚数据上执行 |
| 回滚 | 验收后将测试用 Activated 改回 Deactivated 或删除 (在无订阅阻塞的前提下) |

### 2.3 两套环境验收差异

| 维度 | 测试环境 | 线上环境 |
|-|-|-|
| 目标 | 全量功能与文案验收 | 冒烟 + 关键路径确认发布可用 |
| 用例深度 | 执行第 5 节全部适用用例 | 执行第 4 节线上清单 + 抽样第 5 节 P0 |
| 互斥 / 删除 | 必须测完整弹窗与替换 | 可用预沟通的测试商品测 1 次 |
| 合同 Manage | 各状态操作都要走通 | Active 改地址、Cancel 各 1 次即可; Past due 有样例再测 |
| 真实扣款 | 可用测试支付反复试 | 控制笔数; 确认后尽量退款或取消 |

## 3. 通用前置与通过标准

### 3.1 通用前置

1. 后台左侧可进入 Bundles、Subscriptions、Contracts
2. 至少 1 个已同步 Shopify 商品可用
3. 验收账号对目标店有配置权限
4. 浏览器建议宽度 > 980px 测右侧悬挂; ≤ 980px 测窄屏取消悬挂

### 3.2 通过标准

| 级别 | 定义 | 发布门禁 |
|-|-|-|
| P0 | 主路径不可用、数据错乱、启用互斥失效、拦截不带订阅标识、Activated 未接管 / 错误接管 | 任一失败则测试环境不通过; 线上任一失败则不发布或回滚 |
| P1 | 筛选、文案、空态、分页、气泡、预览联动错误 | 测试环境须修完或有明确豁免; 线上可记问题但不阻断若有豁免 |
| P2 | 样式、悬挂、暗文、次要提示 | 记问题, 不单独阻断 |

### 3.3 界面硬约束 (两环境均查)

- 商家界面不出现 shop_id、内部 schema、webhook、队列等词
- 列表与选择器不展示 Shopify 商品 ID、内部 shop_id (文档明确禁止的位置)
- Bundle ID 展示为数字, 不带 `BND-` 前缀
- Subscription ID 展示完整库编号, 带 `PL-` (如 `PL-1013`)
- Contracts ID 展示数字, 不带 `SUB-` 前缀

## 5. 测试用例 (产品经理可执行)

每条格式: 目的 / 前置 / 步骤 / 期望. 测试环境全跑; 线上只跑标记 P0 及清单「线上」列对应用例.

### 5.1 Bundles 列表与筛选

**TC-B-L01 (P1) 列表默认与进入编辑**

- 前置: 至少 2 条套装
- 步骤: 打开 Bundles → 点某行或 View
- 期望: 按创建时间降序; 进入对应编辑页; 列表无 Delete

**TC-B-L02 (P1) 搜索与 Status 筛选**

- 前置: 有 Activated 与 Deactivated 各至少 1 条
- 步骤: 切换搜索字段与关键词; 筛选 Activated; 点标签 ×
- 期望: 匹配规则符合文档; 页码回 1; 清空后恢复

**TC-B-L03 (P1) 空态**

- 步骤: 无数据店看列表; 有数据时筛到无结果
- 期望: 分别显示 No bundles yet. / No bundles match these filters.

### 5.2 Bundles 新建 / 编辑 / 互斥 / 删除

**TC-B-A01 (P0) 必填校验**

- 步骤: Add bundle 不填名称、不选商品、清掉档或 Price, 点 Add bundle
- 期望: 对应英文报错, 阻断提交, 滚到最上报错处

**TC-B-A02 (P0) 保存 Deactivated**

- 步骤: 填合法数据, Status=Deactivated, 保存
- 期望: toast Bundle saved, 回列表, 商品页不展示该套装

**TC-B-A03 (P0) 启用互斥**

- 前置: 父商品 A 已有 Activated 套装 Old
- 步骤: 新建/编辑另一套装绑 A, Status=Activated, Save
- 期望: 弹 Replace the current active Bundle?; 文案含父商品名、旧名、新名; Cancel 不保存; Replace and activate 后仅新套装 Activated, Old 为 Deactivated

**TC-B-A04 (P1) 保存后订阅引导**

- 前置: 父商品无 BestCheckout 订阅
- 步骤: 首次保存成功 (含首次变为 Activated)
- 期望: 弹 Add Subscribe & Save?; Add subscription 进入新建订阅并预填; Not now 回列表且不建订阅
- 补充: 已有订阅时不弹, 直接回列表

**TC-B-D01 (P0) 有订阅不能删套装**

- 前置: 父商品存在任意状态订阅
- 步骤: Edit bundle → Delete
- 期望: Can't delete this bundle; View subscription 进该订阅编辑页

**TC-B-D02 (P0) 无订阅可删**

- 前置: 父商品无订阅
- 步骤: Delete → 确认 Delete
- 期望: toast Deleted; 该商品页不再用 BestCheckout 购买区

**TC-B-E01 (P1) 未保存与徽章**

- 步骤: Edit 改字段出未保存条; 改 Status 不点 Save; Discard
- 期望: 徽章仍为上次保存状态; Discard 还原进页内容

### 5.3 Subscriptions

**TC-S-L01 (P0) 仅 BestCheckout 来源**

- 期望: 列表无外部导入计划; 无 Source、无 Refresh

**TC-S-A01 (P0) 有套装商品建订阅**

- 前置: 商品有 Activated 套装且多于 1 档
- 步骤: Add subscription 选该商品
- 期望: 显示套装名 + Sold as a bundle; 出现 Subscribed tier、Storefront style; 默认档为套装 Default selection; Bill every 数字跟随该档 Buy qty

**TC-S-A02 (P0) 无套装商品建订阅**

- 前置: 商品无 Activated 套装
- 步骤: 选该商品
- 期望: 出现 Force subscription、Show delivery details; 不出现 Subscribed tier / Storefront style

**TC-S-A03 (P0) 启用互斥**

- 前置: 同商品已有 Activated 计划
- 步骤: 另一计划 Save 为 Activated
- 期望: Replace current active plan?; Replace 后旧计划 Deactivated

**TC-S-D01 (P0) 删除订阅**

- 步骤: Edit → Delete subscription → 确认
- 期望: toast Deleted; 结账不再提供该订阅

**TC-S-L02 (P1) Shown on**

- 步骤: 分别为「有 Activated 套装」「无套装」的计划看列表 Shown on
- 期望: 前者 Product page + Checkout 两枚标签; 后者仅 Checkout

### 5.4 单品订阅匹配 (P0)

前置: 单品无 Activated 套装; 拦截可进结账.

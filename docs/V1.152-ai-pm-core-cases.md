# V1.152 Bundle 与订阅 - AI 可执行的 PM 核心验收用例

## 1. 文档定位

本文件供 AI 按步骤执行产品经理范围内的验收。测试对象是商家可见页面、店铺前台、结账结果和合同页面。

不要求产品经理查看接口、数据库、日志、代码或内部 ID。接口是否被调用, 只通过页面结果、订单结果和合同结果判断。

### 执行规则

- 测试环境执行 TC-01 至 TC-08。
- 线上环境只执行标记为「线上」的步骤, 且只使用测试商品、测试订单或商家明确授权的数据。
- 任一 P0 用例失败, 立即停止后续线上操作, 记录失败证据并通知负责人。
- AI 不得自行删除真实商品配置、取消真实合同或重复提交支付。
- 遇到登录、支付授权、验证码、权限确认或无法判断的数据时, 停止并向用户说明。

## 2. 角色范围

### 产品经理可以验证

- 后台页面是否能完成配置。
- 商品页展示和购买选项是否正确。
- 购物车结账和 Buy Now 是否进入正确购买路径。
- 订单展示的商品、档位、数量、价格和赠品是否正确。
- 合同页面状态、可用操作和页面反馈是否正确。

### 产品经理不验证

- API 是否按指定顺序调用。
- 数据库字段、队列、Webhook、内部 schema 和内部 ID。
- 实际扣款调度、库存服务内部处理和接口性能。
- Shopify 或第三方应用的源代码实现。

## 3. 测试数据

执行前确认以下数据可用:

| 数据编号 | 数据要求 |
|-|-|
| D1 | 单品 A, 没有 Activated Bundle |
| D2 | 商品 B, 有 Activated Bundle, 没有 Activated Subscription |
| D3 | 商品 C, 有 Activated Bundle 和 Activated Subscription |
| D4 | 商品 D, 已有 Activated Bundle 1, 可再创建 Bundle 2 |
| D5 | 商品 E, 已有 Activated Subscription 1, 可再创建 Subscription 2 |
| D6 | 一条 Active、Past due、Cancelled 合同 (测试环境必须有) |

线上环境可以用一个测试商品替代 D1-D5, 但不能使用未获授权的真实商品。

## 4. 用例格式

AI 执行每条用例时必须:

1. 先确认前置条件。
2. 按步骤顺序操作, 不跳步。
3. 每一步记录实际看到的页面结果。
4. 只有所有通过标准满足时才判定通过。
5. 发现失败、数据不一致或需要额外权限时立即停止该用例。

## 5. 核心用例

### TC-01 [P0] Bundle 启用互斥

**目标:** 验证同一商品只能有一个 Activated Bundle。

**环境:** 测试环境必须执行; 线上用 D4 执行一次。

**前置条件:** 商品 D 已有 Activated Bundle 1。

**步骤:**

1. 进入 Bundles, 打开 Bundle 2 的编辑页; 如果没有 Bundle 2, 创建一个绑定商品 D 的 Bundle。
2. 将状态设置为 Activated, 点击 Save。
3. 确认页面出现替换确认弹窗。
4. 点击 Cancel, 回到列表并查看两条 Bundle 状态。
5. 再次保存为 Activated, 点击 Replace and activate。
6. 打开商品 D 的前台商品页。

**通过标准:**

- 弹窗说明 Bundle 1 将被替换。
- 第 4 步后, 两条 Bundle 状态保持原样。
- 第 5 步后, Bundle 1 为 Deactivated, Bundle 2 为 Activated。
- 商品页只展示 Bundle 2 的购买区。

**失败处理:** 任何状态错误或商品页展示旧 Bundle 时, 停止执行并记录截图。

### TC-02 [P0] Subscription 启用互斥

**目标:** 验证同一商品只能有一个 Activated Subscription。

**环境:** 测试环境必须执行; 线上用 D5 执行一次。

**前置条件:** 商品 E 已有 Activated Subscription 1。

**步骤:**

1. 进入 Subscriptions, 打开 Subscription 2 的编辑页; 如果没有, 创建一个绑定商品 E 的计划。
2. 将状态设置为 Activated, 点击 Save。
3. 确认页面出现替换确认弹窗。
4. 点击 Cancel, 查看两条计划状态。
5. 再次保存为 Activated, 点击 Replace and activate。
6. 打开商品 E 的商品页或结账页。

**通过标准:**

- 弹窗说明 Subscription 1 将被停用。
- Cancel 后数据不变。
- Replace and activate 后 Subscription 1 为 Deactivated, Subscription 2 为 Activated。
- 商品页或结账页使用 Subscription 2。

### TC-03 [P0] 商品页接管规则

**目标:** 验证 Bundle 状态决定商品页是否被接管。

**环境:** 测试环境必须执行; 线上至少执行无 Bundle 和有 Bundle 两种。

**步骤:**

1. 打开 D1 商品页。
2. 打开 D2 商品页。
3. 打开 D3 商品页。
4. 分别观察购买区域、档位和购买方式。

**通过标准:**

- D1 不接管 Shopify 变体区, 仍可正常加购和 Buy Now。
- D2 接管购买区域, 展示 Bundle 档位, 只有一次性购买。
- D3 接管购买区域, 展示 Bundle 档位, 同时有一次性和订阅省。

### TC-04 [P0] Bundle 购买结果

**目标:** 验证买家选择的 Bundle 能正确进入结账和订单。

**环境:** 测试环境必须执行; 线上执行一笔小额或可退款订单。

**前置条件:** D2 或 D3 的商品页已正确展示 Bundle。

**步骤:**

1. 在商品页选择一个 Bundle 档位。
2. 核对页面显示的档位、数量和价格。
3. 如果页面有订阅选项, 分别选择一次性和订阅省各执行一次; 线上至少执行商家授权的一种。
4. 点击购买并进入结账。
5. 检查结账页购买方式。
6. 完成测试订单, 查看订单详情。

**通过标准:**

- 结账页保留正确的购买方式, 不能再切换成另一种方式。
- 订单中的档位、数量、价格和赠品与商品页选择一致。
- 没有 Activated Subscription 时, 商品页不出现订阅选项。
- 订单完成后能在 BestCheckout 订单页面看到对应订单。

### TC-05 [P0] 单品购物车与 Buy Now 拦截

**目标:** 验证单品的购物车结账和 Buy Now 都经过同一购买判断。

**环境:** 测试环境必须执行; 线上执行标记为线上的一组。

**前置条件:** 使用没有 Activated Bundle 的单品。

**步骤 A - Force subscription:**

1. 为该单品创建 Activated Subscription, 打开 Force subscription。
2. 商品页不勾选订阅, 分别通过购物车结账和 Buy Now 购买。

**期望:** 两条路径都按订阅购买。

**步骤 B - 用户勾选订阅:**

1. 使用有 Activated Subscription 的单品。
2. 在商品页或结账行勾选订阅。
3. 分别通过购物车结账和 Buy Now 购买。

**期望:** 两条路径都按订阅购买; Buy Now 即使跳过购物车也保留订阅选择。

**步骤 C - 无匹配计划:**

1. 勾选订阅, 但使用没有绑定该单品的计划或没有计划的单品。
2. 分别通过购物车结账和 Buy Now 购买。

**期望:** 两条路径都按一次性购买, 不因 Shopify Selling Plan 的勾选而显示为 BestCheckout 订阅。

**线上:** 至少执行步骤 A 和步骤 B 各一次。

### TC-06 [P0] 删除保护

**目标:** 防止删除 Bundle 后破坏已有订阅配置。

**环境:** 测试环境必须执行; 线上只操作授权的测试商品。

**步骤:**

1. 在有任意状态 Subscription 的商品上打开 Bundle 编辑页, 点击 Delete。
2. 观察拦截弹窗, 点击 Cancel 或关闭弹窗。
3. 确认 Bundle 仍存在。
4. 在没有 Subscription 的商品上删除 Bundle, 在确认弹窗中点击 Delete。
5. 打开该商品页。
6. 删除一条 Subscription, 再打开该商品的结账页。

**通过标准:**

- 有 Subscription 时不能删除 Bundle, 弹窗提供进入该 Subscription 的入口。
- 关闭弹窗或 Cancel 不修改数据。
- 无 Subscription 时确认删除后, Bundle 消失, 商品页不再使用 BestCheckout 购买区。
- 删除 Subscription 后, 结账不再提供该计划。

### TC-07 [P0] 合同管理

**目标:** 验证合同页面根据状态展示正确操作。

**环境:** 测试环境必须执行; 线上至少打开合同详情, 修改地址需获得商家确认。

**步骤:**

1. 打开 Active 合同, 检查 Manage 区域。
2. 修改收货地址, 点击 Save。
3. 打开 Past due 合同, 检查 Manage 区域; 如有测试样例, 点击 Retry payment now。
4. 打开 Cancelled 合同, 检查 Manage 区域。
5. 在 Active 或 Past due 测试合同上点击 Cancel subscription, 在确认弹窗中确认。

**通过标准:**

- Active 显示 Edit shipping address 和 Cancel subscription。
- Past due 显示 Retry payment now、Update payment method 和 Cancel subscription。
- Cancelled 不显示可执行操作。
- 地址保存后, Customer 和 Ships to 显示新地址。
- Retry payment now 后状态显示 Active。
- 取消后状态显示 Cancelled, 有结束日期, 不再有下次扣款, 且不再显示 Manage 操作。

### TC-08 [P1] 保存后的订阅引导

**目标:** 验证 Bundle 保存后是否正确引导创建 Subscription。

**环境:** 测试环境执行; 线上只查看或使用授权的测试商品。

**步骤:**

1. 保存一个商品上首个成功的 Bundle, 且该商品没有 BestCheckout Subscription。
2. 检查是否出现 Add Subscribe & Save? 弹窗。
3. 点击 Not now, 确认回到 Bundles 列表且没有创建 Subscription。
4. 再次保存 Bundle, 点击 Add subscription。

**通过标准:**

- 没有 Subscription 时出现引导。
- Not now、关闭按钮或遮罩不会创建 Subscription。
- Add subscription 进入新建页, 商品和 Bundle 已预填, 默认档正确。
- 已有 Subscription 时保存 Bundle 不出现该引导。
